- **16C test migration (NOT a weakening — verified)**: 16D changes UPDATE from in-place overwrite (1 row) to archive-old+insert-new (2 rows). The two edited 16C tests now assert `len(active)==1` (valid_to IS None) AND `len(archived)==1`/content checks — STRONGER than old `_fact_count==1`. A dedup/supersede regression (both stay active) → len(active)==2 → still FAILs. Legitimate policy selection, documented.
- **TOKI dispatch** = on the MATCHED (old) fact's stored `write_policy` (manager `_resolve_conflict`, manager.py:701). last-write-wins/merge → `_supersede_fact` (old valid_to=now + superseded_by_fact_id, tombstone old vector, insert new). evidence-weighted → incoming conf > old supersedes, ≤ is NOOP returns old_id (no write). await-confirmation → both active + cross-linked `conflicting_fact_ids` (JSON, read-modify-write union). `_choose_write_policy`: _MERGE_HINTS (work/married/...) then _EVIDENCE_HINTS (allergic/...) then category map (preference→evidence) else last-write-wins.
- **merge window edge**: `old.valid_to == new.valid_from` relies on both being SQLite `datetime('now')` (sec resolution) in same second (new inserted then old superseded). Passed; MINOR flake risk if it straddles a second boundary.
- **Migration** (`_migrate_memory_facts_quality_columns`, database.py:367, called init_db:252): idempotent PRAGMA check-before-ALTER. valid_to REUSED from 16C (not re-added). valid_from has NO constant default (SQLite forbids non-const DEFAULT on ADD COLUMN) → backfilled `UPDATE...WHERE valid_from IS NULL` + `memory_facts_valid_from_default` AFTER INSERT trigger (sets valid_from=created_at). Trigger updates ONLY valid_from → does NOT fire memory_facts_fts_update (which is AFTER UPDATE OF content,category) → no FTS interference.
- **Decay** (`run_decay`, manager.py:960): `strength *= exp(-days/half_life_days)`; days fallback last_recalled_at→valid_from→created_at→0.0 (undateable never archives). Hooked in main `_consolidation_loop` (main.py:214) AFTER run_consolidation, guarded `if today != last_decay_day` (loop ticks 600s/10min → would over-decay 144x without guard). Wrapped in own try/except (CancelledError re-raised). strength<DECAY_THRESHOLD(0.1) → valid_to set (archived not deleted) + vector tombstoned. Batch DB write via `apply_decay` executemany.
- **FAISS tombstone** (vector_store.py:154 `tombstone_fact_id`, set `_tombstoned`): applied on ALL 3 paths — supersede (`_supersede_fact`), DELETE (`_apply_extractions`), decay-archive (`run_decay`). `search()` over-fetches `top_k+len(tombstoned)` then skips tombstoned positions → still returns top_k LIVE. Persists in .meta.json `tombstoned` array across save/load. Fixes 16C latent bug: `_find_similar_fact_id` searches FAISS directly (bypasses valid_to row filter) so without tombstone a superseded fact could be returned as dedup target. `_tombstone_vector` (manager.py:573) degrades to no-op if store lacks method (old fakes) — valid_to filter still protects recall.
- **Recall exclusion**: candidate loop skips `if meta.get("valid_to")` (manager.py:1124) — covers archived/superseded/decayed. Tombstone is the earlier defense layer.
